# 番茄联动：第二阶段

范围：正计时、手动结束；实现应用层和持久化逻辑，暂不注册桌面命令、启动后台任务、修改安装版或连接真实记录库。

## 已实现的接口

`TimerService::tomatodo_link(LinkCommand)` 与普通计时命令共用服务层互斥锁。

- `Observe(Observation)`：消费观察结果。闲置到正计时开始时自动创建第一段；持续采样不会重复开段。
- `EndSegment`：结束本段、入独立待补记队列、保留来源任务；即使全局使用连续打点，本段结束后仍等待手动开始。
- `StartNext`：只在五秒内读到来源正计时进行中、且没有其它记录占用时开始；继承最新来源标题，不复制前段备注。
- `SaveNote` / `SkipNote`：按段 ID 和版本号单独确认，不依赖单个 UI 补记槽；可在下一段开始、来源结束以后补写前段。
- `tomatodo_link_state()`：读取持久化关联、当前段及待补记 ID 队列。

来源结束进入休息时关闭关联段并解除关联；跳过休息不新建记录。停段后来源结束，不产生空段。来源暂停会关闭当前段并保留备注，恢复时可自动开新段以排除暂停空档；用户主动停段优先，后续暂停/恢复不能取消用户停段。

首次连接已经进行中的专注，仅建立关联，须手动开始本段，避免补写没有实际观察到的时间。正常连接时的开始/结束使用本机处理时间，存在观察延迟，不声称与源时间毫秒级一致。

## 存储与保护

关联与队列存入既有 `runtime_state` 的 `tomatodo.link.v1` 键，无新增迁移。新增 `commit_runtime` 端口将联动上下文、时间段和事实一起提交，数据库异常整体回滚；未实现该能力的存储端口返回错误，不降级为分开写入。

结束段携带 `awaitNote` 标记，待补记内容确认前不允许自动发布，即使全局补记提示关闭也一样。保存/跳过备注时解除等待。每条开段审计事实记录来源会话，供第三阶段建立历史导入映射；当前尚未修改历史导入器。

拒绝乱序、超过五秒的过期或异常未来状态；不支持倒计时。断连不会结束记录。断连后同一会话仍在进行，保留原段并标记不确定空档；断连后来源已结束或换任务，拒绝猜测，交给后续界面的人工核对。无关 active 或暂停记录不会被接管。

已保存的来源开始时间高水位防止已结束会话重复开段；同名但新开始时间的下一场可以正常开段。重启后恢复关联和所有待补记 ID。损坏的上下文报错，不静默清空。

## 验证

- 18 项专门测试使用 SQLite 内存库和临时文件，覆盖完整分段、备注、重复采样、暂停、冲突、断连、过期状态、文件重开及事务故障注入。
- 工作区完整 Rust 测试：246 项通过，0 失败。严格 Clippy 全工作区检查通过。
- 重现演示：`cargo run -p dotlog-storage --example tomatodo_link_demo --offline`，只写内存 SQLite，生成两段“线代”记录并独立保存第一段备注。

## 第三阶段装配要求

1. 观察器 JSON 必须验证 `connected/compatible/countUp/state/sessionKey/startMs/observedAt` 后转换为 `Observation`；未知/缺字段不能当作空闲。
2. 后台和界面使用同一个 `TimerService` 实例。显式启用后运行后台观察；首次运行与中断必须发送 Unknown/建立基线，不能回放历史为新事件。
3. 联动开启时，分段按钮、全局快捷键与托盘入口全部经过本模块；不能仍调用普通 pause/resume，否则会重新合并为同一记录。普通 API 改变关联段时，本模块会拒绝继续自动处理，需人工核对。
4. 界面按完整队列展示待补记，而不是覆盖当前 pendingNote；编辑保留版本检查，已被外部删除/修改的段明确提示。
5. 显示连接状态、冲突、间断与补记状态，提供核对/解除关联流程。第二阶段尚未实现这些交互入口。
6. 接入历史导入去重和桌面恢复机制，保证仅在用户启用联动且恢复检查通过时写入。此模块尚不构成生产后台自动化或已安装应用验收。
