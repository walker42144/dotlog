# 打点 DotLog · 开发路线、测试与验收

版本：v0.1 ｜ 原则：每个里程碑都能独立验收，未通过不进入下一阶段

---

## 1. 里程碑

### M0 · 工程骨架（可运行空壳）

交付：

- Cargo workspace + npm workspaces；`apps/desktop`（Tauri 2 + Vite + React 19 + TS strict）。
- `crates/domain` 状态机（含 `stop` / `chain` 两种模式）+ `FakeClock` 单测全部转换与不变量。
- `crates/storage` 迁移 0001、仓储接口实现、临时库集成测试（唯一 active、回滚）。
- `crates/application` 用例壳 + `timer_get_state` 一条完整链路。
- `packages/ipc` 生成绑定，前端能显示“空闲 / 记录中”两种状态。

退出条件：

1. `npm run tauri dev` 启动出窗口。
2. `cargo test` 全绿；`npm run typecheck` 通过。
3. 数据库文件在 `%APPDATA%\dotlog\dotlog.db` 正确创建，迁移可重复执行。

### M1 · 打点闭环

交付：

- `timer_start / punch / pause / finish / undo` 全部命令。
- 今天页：大按钮、当前用时、只读时间线、今日统计。
- 补记浮层：标题、最近标签、备注、Enter 保存、Esc 跳过。
- 托盘图标与菜单、全局快捷键、单实例、关窗到托盘、启动自启开关。
- 15 秒短段提示与撤销。

退出条件：

1. 从按下快捷键到补记保存平均 ≤ 5 秒。
2. 连续使用 3 天，无数据丢失、无重复段。
3. 关窗后仍可打点；第二实例唤起主窗口。

### M2 · 时间线编辑

交付：

- 拖拽边界、补录、删除、拆分、合并；冲突预检与裁剪选项。
- 撤销扩展到编辑操作（Ctrl+Z）；跨日切片展示与跨日未结束处理。
- 历史页月历 + 列表 + 基础筛选。

退出条件：

1. 用户能在 2 分钟内修正一天的漏记。
2. 任意编辑后，当天总时长 = 各段之和，误差 0。
3. 跨日记录在两天视图中片段和等于原段。

### M3 · 数据与统计

交付：

- 日/周/月统计、分类占比、完整率、下钻。
- JSON/CSV 导出、导入（CSV，带预览与冲突报告）。
- 滚动备份（`VACUUM INTO`）、恢复演练、备份列表。
- 设置页全部项持久化。

退出条件：

1. 统计数字与原始记录逐项一致（脚本比对）。
2. 重装前导出 → 新库导入后数据一致。
3. 恢复备份后应用正常启动且 `quick_check` 通过。

### M4 · 稳定性

交付：

- 休眠/长间隔、时钟跳变、崩溃恢复、孤儿 active 处理。
- 诊断日志、诊断包、启动完整性自检。
- 10 000 段数据下的性能验证。

退出条件：

1. 断电、强制结束进程、休眠唤醒、跨时区场景测试全部通过。
2. 7 天人工长测：无丢失、无重叠、无统计偏差。
3. 冷启动 < 1.5 s，打点 IPC p95 < 50 ms。

### M5 · 扩展与发布

交付：

- `plugin-sdk` v1 + `plugin-host`（启停、能力裁决、超时、panic 隔离）+ 示例插件。
- outbox worker 与重试策略、失败可视化与手动重试。
- Memos 单向发布（版本探测、幂等、断网补发）。
- AI Provider 接口与建议确认流程（不覆盖事实）。
- NSIS 安装包、自动更新、隐私说明、反馈入口。

退出条件：

1. 示例插件独立启停；禁用后核心打点无影响。
2. 断网期间打点正常，恢复后发布不重复。
3. 5–10 名用户完成一周试用，无 P0 问题。

## 2. 任务依赖顺序

```text
M0: workspace → domain 状态机 → 迁移 0001 → storage 仓储 → application 用例 → IPC 生成 → 空壳 UI
M1: commands → 今天页 → 补记 → 托盘/快捷键/单实例 → 短段撤销
M2: 编辑/补录 → 冲突校验 → 撤销扩展 → 跨日 → 历史页
M3: 统计查询 → 分析页 → 导出/导入 → 备份/恢复 → 设置
M4: 恢复流程 → 心跳/时钟 → 诊断 → 性能
M5: plugin-sdk → host → outbox → Memos → AI → 打包
```

规则：**domain 与 storage 的测试必须先于 UI**；UI 只消费已验证的契约。

## 3. 测试矩阵

| 层 | 工具 | 覆盖 |
|---|---|---|
| 领域单元 | `cargo test` + `FakeClock` | 状态转换、不变量、撤销、跨日切片、统计边界（见 domain-model §12） |
| 属性测试 | `proptest` | 随机打点序列下“无重叠、单 active、总时长守恒” |
| 数据库集成 | `cargo test` + 临时库 | 迁移、事务回滚、唯一索引、软删除、备份恢复 |
| 应用层 | 假仓储 + 假时钟 | 用例编排、事件顺序、错误映射 |
| 前端组件 | Vitest + Testing Library | 补记浮层、时间线渲染、拖拽计算、空状态 |
| 端到端 | Playwright（Web 构建 + mock IPC） | 首次打点 → 补记 → 编辑 → 导出 |
| 桌面集成 | `tauri-driver`（M4 起） | 托盘、快捷键、单实例、休眠唤醒 |
| 人工长测 | 真实使用 7 天 | 误点、断电、跨时区、大量记录 |

持续集成门槛（任一不通过即阻断）：

```text
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
npm run typecheck
npm run test
npm run build
生成绑定无 diff
```

## 4. MVP 验收指标

| 指标 | 目标 |
|---|---|
| 一次切换（打点到补记保存） | ≤ 5 秒 |
| 异常关闭后已落盘记录 | 0 丢失 |
| 当天总时长与分段求和误差 | 0 |
| 修正一天漏记耗时 | ≤ 2 分钟 |
| 不开启集成时的联网请求 | 0 |
| 段重叠 | 0（含导入后） |

## 5. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 功能膨胀拖慢核心 | 打点变慢、周期失控 | 冻结 M0–M5 范围；新想法进 backlog |
| 计时不可信 | 用户放弃 | 单事务、恢复提示、空白可视化、统计可下钻 |
| 默认 `stop` 模式增加点击次数 | 记录意愿下降 | 保留 `chain` 设置；一键切换并说明差异；复盘页突出空白 |
| 插件破坏数据 | 损坏或泄露 | 能力裁决、无 DB 句柄、快照事件、密钥入钥匙串 |
| 同步冲突 | 重复/覆盖 | Memos 首版单向；`external_id` + outbox 幂等 |
| AI 误改事实 | 记录失真 | 建议与事实分离，用户确认后写入 |
| 跨平台差异 | 快捷键/托盘不一致 | Windows 首发；系统能力封装为 trait |
| SQLite 单写竞争 | 偶发 `E_DB_BUSY` | 单连接 + `busy_timeout` + 命令串行化 |
| 迁移失败 | 用户无法启动 | 迁移前备份、事务回滚、checksum 校验 |

## 6. 完成定义（DoD）

每个功能合入需同时满足：

1. domain 规则有单元测试；涉及持久化的有集成测试。
2. IPC 类型由 Rust 生成，前端无重复定义。
3. 错误路径有对应错误码与中文文案。
4. 操作可撤销或可修正（除明确不可逆的恢复/删除确认）。
5. 不新增未声明的第三方依赖；新增依赖需在 `architecture.md` 记录理由。
6. 日志不含密钥与备注全文。
